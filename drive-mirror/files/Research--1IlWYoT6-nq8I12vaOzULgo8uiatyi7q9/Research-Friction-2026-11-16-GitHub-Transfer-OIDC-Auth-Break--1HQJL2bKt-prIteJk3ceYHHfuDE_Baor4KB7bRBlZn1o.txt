1. Executive Summary & Verdict
* Verdict: KILL
* Core Finding: 该 Signal 反映的是 GitHub Actions 自 2026 年 7 月起推行不可变主体声明（immutable subject claims，sub 包含 owner-id 与 repo-id）后，在企业进行跨组织仓库 Transfer 或重命名时，导致下游基于名称的云端 OIDC 信任策略（AWS IAM Role / Azure Entra ID / GCP Workload Identity）失效、GitHub Actions 认证失败的问题。
* Kill 核心判定理由:
   1. 配置级一次性维护，无独立软件付费意愿（Gate 1 失败）：仓库跨组织 Transfer 属于偶发性低频管理行为（仅在 M&A、部门重组或开源项目移交时发生）。修复该摩擦的实际操作仅为在 Terraform 代码或云控制台中将 OIDC Trust Policy 的 sub 匹配条件更新为包含数字 ID 的新格式（熟练工程师耗时 2–5 分钟）。工程团队绝不会为此类极低频的配置微调单独采购外部商业软件或付费服务。
   2. 企业最高安全边界禁止外部介入（Gate 4 失败）：云端 OIDC Federated Identity 是企业生产环境核心权限的信任锚点。企业安全与合规团队有严格的权限隔离要求，绝对不可能向任何第三方外部未授信工具授予修改其 AWS IAM / Azure Entra ID 信任策略的高危写权限。该摩擦完全属于企业内部 DevOps 的职责范畴，外部第三方软件缺乏商业捕获与产品化介入通道。
2. Signal 原始事实核查与背景
* 现象描述: 自 2026 年 7 月 15 日起，GitHub 对新建、重命名或 Transfer 的代码仓库强制使用包含数字 ID 的不可变 subject claim。若企业此前在 Terraform 中将 OIDC 信任策略硬编码为 repo:org/repo:ref:... 格式，Transfer 后因 sub 变更为 repo:OWNER@OWNER-ID/REPO@REPO-ID:...，导致 GitHub Actions 部署流水线在首次运行时报认证错误。
* 证据链核查:
   * Zenn 实践文章（2026-11-09）：Zenn: 組織をまたいだリポジトリの引き継ぎをする時に気をつけること —— 详细记录 Transfer 时的 OIDC sub 变更及在 Terraform 中预先添加新格式 federated credential 的避坑步骤。
   * Hat Boy Software 深度技术解析（2026-10-09）：Hat Boy Software: GitHub immutable OIDC subjects —— 阐明机制原理及官方设计初衷。
   * GitHub 官方 Changelog（2026-04-23）：GitHub Changelog: Immutable subject claims for GitHub Actions OIDC —— 证实属于平台既定安全架构升级。
* 原始 Signal 评级: 原始信号标记为 Structural。
