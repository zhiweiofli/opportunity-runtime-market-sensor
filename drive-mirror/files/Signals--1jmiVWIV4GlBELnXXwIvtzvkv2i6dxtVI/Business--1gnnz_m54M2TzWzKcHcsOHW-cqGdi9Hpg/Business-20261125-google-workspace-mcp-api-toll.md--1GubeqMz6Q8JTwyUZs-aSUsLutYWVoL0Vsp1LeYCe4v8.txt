Signal ID: Business-20261125-google-workspace-mcp-api-toll
* Type: Business
* What Changed: 2026 年 11 月 24 日（UTC），Google Workspace 正式上线标准化分级定价与配额控制台（Standard Tier 与 Scaled Tier），并同步发布《Workspace AI Tools Addendum》法务条款，针对 AI 智能体（AI Agents）访问 Gmail、Calendar 与 Drive 数据 建立强制性的 MCP 通道隔离与首请求起扣收费站（属于 New Toll Booth 与 Budget Migration）：
   * 强制智能体改道 MCP（2027-02-01 生效）：依据新发布的《Workspace AI Tools Addendum》，任何由 AI Agent、AI Harness 或 AI 模型驱动的工具访问 Google Workspace 数据，必须强制使用 Google 官方 MCP Servers（如 gmailmcp.googleapis.com、calendarmcp.googleapis.com、drivemcp.googleapis.com 等 8 个 GA 服务）；若 AI Agent 继续直连 REST API，无论项目是否付费，均将被强制锁死在 Standard Tier 配额上限。
   * Standard vs. Scaled Tier 非对称计费分水岭（2026-11-24 开放配置，2027-04-01 强制扣费）：
      * Standard Tier 免费但限制所有 GA MCP Server 每日每项目每产品最高 5,000 次请求（无法申请提额，亦不适用"内部使用豁免"）。
      * 一旦项目为突破 5,000 次/日限制而升级至 Scaled Tier，整个 Cloud Project 的免费 MCP 额度将被彻底清零（整项目维度生效，不可单接口拆分）：传统 REST API 在 Scaled Tier 仍享有海量每日免费额度（如 Gmail Light 7,000 万次/日），但 Gmail、Calendar 与 Drive MCP Server 的每日免费额度为 0，自第 1 次成功请求（HTTP 2xx）起即全面按量扣费。
   * 复合放大与"失败亦扣费"规则：部分复合 MCP 工具（如 list_drafts、search_threads）单次调用即按 10 个计费单元（Billing Units） 扣费；messages.get/threads.get 拉取完整正文（full/raw）的配额消耗是 metadata/minimal 的 3 倍；且由于 MCP JSON-RPC 参数错误或执行失败仍返回 HTTP 200 (isError: true)，报错的工具调用同样计入扣费。
* Money: 直接重塑所有依赖 Google Workspace 数据（邮件、日程、云盘）的企业自动化与 AI Agent 研发预算：
   * 四档单价（每 1,000 次计费单元）：
      * Light：$0.10 / 1K（如 get_file_metadata、list_labels）
      * Medium：$0.20 / 1K（如 create_draft、create_file、messages.get）
      * Plus：$0.25 / 1K（如 search_files、所有 Calendar API 与 Calendar MCP 调用）
      * Premium：$0.50 / 1K（如 download_file_content、read_file_content、get_thread、search_threads）
   * REST API 对比 MCP 的巨大资金剪刀差：在 Scaled Tier 下，Gmail REST API 每天有 7,000 万（Light）/ 1,000 万（Medium）/ 100 万（Premium）免费额度，Drive REST API 有 2,000 万/700 万/400 万/100 万免费额度，Calendar REST API 有 100 万免费额度；而 Gmail/Calendar/Drive MCP 每日免费额度为 0。以 Agent 高频调用 search_threads（Premium 档且占 10 个计费单元）为例，每次搜索即耗资 $0.005；月消费超过 $20,000 起才触发 17%–40% 的阶梯折扣（$0–$20,000 区间 0% 折扣）。Google Cloud Console 已于 11 月 24 日同步上线 Cost estimator 与 Project billing usage 计费估算面板。

   2. 隐藏的计费倍增器制造极高的 FinOps 浪费（事实/推断）：由于存在四大计费放大陷阱——（1）项目级一刀切关闭 5,000/日免费额度；（2）search_threads/list_drafts 单次算 10 个计费单元；（3）默认 full 格式耗费 3 倍额度；（4）JSON-RPC 报错 HTTP 200 isError: true 照常扣钱——未经优化的原生 Agent 框架（如直接把 MCP 挂进 LangChain/Claude）在生产环境中极易出现账单雪崩。
   3. 小团队轻资产进入节点与 Capture 路径（推断）：
      * Google Workspace MCP 节流网关与参数防错中间件（MCP FinOps Proxy）：3–5 人团队可构建透明代理中间件：在请求抵达 gmailmcp/drivemcp 前执行本地 JSON Schema 强校验（拦截会触发 isError: true 的无效调用以免白交钱）、自动强制降级为 metadata/minimal 两段式按需拉取（削减 66% 正文读取配额）、对多项目路由进行 Standard（每日 5,000 免费额度）与 Scaled 隔离分流，并拦截 Agent 死循环重复调用 10x 计费的 search_threads。
      * 合规事件驱动同步桥接层（Event-Driven Workspace Bridge）：结合免手续费或低配额的 Workspace Events 推送与轻量状态索引，替代 AI Agent 对邮件和日历的高频轮询（需严格遵循 Addendum 中关于衍生数据留存期限的合规约束）。
