# Market Sensor V1：历史量价异常监测试运行

## 1. 本轮决定与边界

用户在云端验收 PR #1 合并后，授权由本会话完善需求并让 Codex 开工。本规格把未定项落实为**本轮提出、可更改的试运行默认值**，不是此前已确认的投资偏好，也不是验证过收益的交易规则。目标是从单日演示升级为可重复运行、有历史比较和质量过滤的真实数据监测。当前线上仍为 0.2.0；本规格的 0.3.0 是开发目标，实施/验收后才更改实际任务版本。

沿用五角色及 Market 的 GitHub Actions + Python + Tushare Pro。保留六份原稿与 PROJECT_GUIDE 原文，以本文件补充可执行口径。确定性代码负责取数、计算、筛选、排序和批内去重。没有交易、收益承诺、回测盈利结论、LLM 行情计算、数据库、队列、新角色或统一 Runtime。

## 2. 观察范围与默认参数

第一版仅观察固定小名单中的 A 股日线，避免新增全市场发现、指数成分、估值或日历接口权限依赖。种子名单仅用于起跑，不声称覆盖全市场、代表某指数或适合投资；流动性必须由每轮数据过滤，不能因进入名单就假定通过。

| 配置 | 本轮试运行默认值 | 语义 |
| --- | --- | --- |
| 观察名单 | 000001.SZ、000333.SZ、000651.SZ、600036.SH、600519.SH、601318.SH | 固定 6 个代码；不是推荐买卖；本版最多 20 个去重代码 |
| 数据源 | Tushare Pro daily，经 HTTPS | 沿用已验证入口；历史区间仍须另验 |
| 拉取区间 | 截至 as_of_date，向前 550 个自然日 | 查询窗口；不等于有效交易样本数 |
| 历史比较样本 | 252 个此前有效日线观察 | 每个评价日单独取此前样本，严格排除评价日及未来 |
| 最少有效记录 | 259 条（含目标日） | 满足最近 3 个评价日各自的 5 日收益及 252 个历史基准 |
| 价格变化 | 5 日复合收益绝对值至少 5%，且历史经验分位至少 99% | 两条件同时成立；仅统计异常 |
| 成交活跃度 | 当日成交额 / 此前 60 个有效日成交额中位数至少 2 | 不把成交额当净资金流或可捕获利润 |
| 持续性 | 目标日命中，且最近 3 个评价日中至少 2 日同方向命中 | 单个价格跳动不输出候选；3 个观察日期跨度不超过 7 个自然日 |
| 流动性 | 目标日前 20 个有效日均成交额至少人民币 1 亿元，目标日成交额为正 | daily amount 的千元先换为元；不能证明用户容量/滑点可接受 |
| 历史新鲜度 | 目标日必须有记录；最近 60 条观察跨度不超过 120 个自然日 | 长期缺失/停牌不得靠很老数据补齐；不声称已验证完整交易日历 |
| 定时 | 周一至周五 20:17，Asia/Taipei | 工作日触发，不承诺每次都是交易日或准点执行 |
| 每轮候选上限 | 5 条 | 截断前保留全部命中数量及排序依据，不偷偷丢弃 |

以上参数集中于一个版本化文件 `config/market-v1.json`，不要散落在 Prompt 或多个 workflow 中，也不建设通用配置系统。报告保存实际配置及 SHA-256。名单/规则参数改动属于行为变更，按 spec → task/code/config → version → CHANGELOG 追溯。

本轮只做一个规则 `price_volume_stress_v1`。不实现跨资产相对价值、真实净流量、Carry/Basis、期权或估值规则；不能把量价异常强称 Flow Shift/错价结论。

## 3. 数据契约与计算

只依赖 daily 的 `ts_code, trade_date, close, pct_chg, vol, amount`。代码/日期严格匹配请求，校验数值有限、close>0、vol/amount>=0、pct_chg>-100；同代码同日重复记录报错，不静默选择。按日期升序计算，不能假定 API 返回顺序。报告保留请求区间、实际返回范围、每标的有效行数、原始行及取数时间。API 返回越界/未来日期为契约错误，不能悄悄算入历史。

Tushare 返回未复权价格，本轮不以未复权 close 的比值计算跨日收益。令百分数 `p_i=pct_chg_i/100`：

`R5(d) = product(1+p_i, i 为截至 d 的最近5个有效日) - 1`。

历史基准是 `d` 之前 252 个有效日各自的 `abs(R5)`；经验分位 `P(d)=count(历史 abs(R5) <= abs(R5(d)))/252`，相等计入。价格条件为 `abs(R5(d))>=0.05 AND P(d)>=0.99`。因此全零历史且当日零变化不能因分位为1被误报。历史基准既不能含 d，也不能借未来数值补齐。

成交条件 `A(d)=amount(d)/median(amount 在 d 前60个有效日)`，中位数偶数样本取中间两数平均；分母<=0 不计算、不输出候选。单日命中 `H(d)` 是价格条件和 `A(d)>=2` 同时成立。

目标日 t 必须 H(t)=true，且 t、前1、前2个有效观察中至少有一个此前观察 H(d)=true 且 sign(R5(d))=sign(R5(t))。随后检查流动性/新鲜度。两日前命中而今日不命中不输出；正负方向相反不算持续。`persistence=持续` 只描述本规则连续观察，额外保留具体日期/命中掩码，不推断经济持续性或“正在扩大”。

排序依次为历史分位降序、abs(R5)降序、A(t)降序、ts_code升序；最多5条。Signal ID 由规则 ID、目标日期、代码构成，不含随机数；同一批次同代码只一条。相同原始输入/配置的数值结果、ID、排序必须可复现，取数/运行生成时间可以不同。跨运行不建去重数据库；人工交接不得把相同日期/ID/配置的重复实跑当新证据，现有 Researcher 观察键协议保持原样。

## 4. 日期、空数据及失败

手动支持显式 `as_of_date=YYYYMMDD` 以便历史重放；默认和 schedule 的目标日期是执行时 Asia/Taipei 的当前日期。拒绝未来日期，不自动偷偷改为上个有行情的日期。相同日期重跑仍要显示实际取数时间和配置。

目标日期没有日线记录时记该标的 NO_DATA，不拿旧行情当今日。没有已实测可用的 trade_cal 时，不解释为已确认休市；可能是休市、停牌、尚未入库或数据缺失。第一版不增加 trade_cal/stock_basic/daily_basic 必需依赖，不扩大 Secret 权限或购买数据。

每个标的记录 MATCH / NO_MATCH / NO_DATA / INSUFFICIENT_HISTORY / LOW_LIQUIDITY / STALE_HISTORY / ERROR 及理由、计数。预期范围为名单全集，报告列出成功、过滤、缺失、失败名单和 coverage_complete，不能因跳过几个标的就声称全覆盖。

`coverage_complete=true` 仅在名单每个标的都完成当日评估（MATCH / NO_MATCH / LOW_LIQUIDITY）时成立；含任何 NO_DATA / INSUFFICIENT_HISTORY / STALE_HISTORY / ERROR 即为 false。LOW_LIQUIDITY 是已完成过滤，不等于数据缺失。

运行级沿用 SIGNALS / NO_MATCH / NO_DATA / ERROR，并新增 INSUFFICIENT_DATA：全无目标日行→NO_DATA；有新鲜有效数据但全部无法满足历史/质量要求→INSUFFICIENT_DATA；有完成评估的合格数据但无命中（含流动性过滤）→NO_MATCH；有候选→SIGNALS。任何网络/API/格式/重复/数值契约错误→ERROR，非零退出，整轮 signals 为空，仍保存诊断报告。其余无候选状态退出0，但不能写成“没有市场异常”。缺 Secret 绝不回退 fixture。

串行请求，正常请求之间至少2秒，单次超时30秒；仅对临时网络失败最多额外重试2次，退避2/5秒，遵守节流。API权限/参数错误不无限重试、不回显原始响应或凭据。工作流超时15分钟；最多20代码的完整运行可用性须实测，超时不能签完整成功。不并发扩大全市场取数。

## 5. 输出与研究边界

历史模式新增实际配置/哈希、as_of_date、取数区间、逐标的状态和覆盖信息；保留现有报告基础字段、完整原始 observations、signals、task_version。每条候选保留 Signal 协议与 Market 角色字段，另列 R5、历史分位/样本数、成交倍数、20日均成交额、实际命中日期、历史范围及质量判断。接口说明与行情来自同一提供者，不冒充独立证据。不得输出证券买卖方向、目标价、仓位、收益率预测或交易指令。

真实 Tushare 历史监测为 `demo_only=false`、`rule.status=trial`；它是真实测量的试运行规则，不是已验证的错价/策略。所有 fixture（含历史规则 fixture）仍 `demo_only=true`、`research_eligible=false`，明确 synthetic。

**本阶段统计候选仍 `research_eligible=false`**：只凭量价不能证明潜在经济机制与成本条件已满足。Possible Mechanism 可写“交易活跃度与重新定价同时增强，可能与信息重估/短期流动性压力有关，尚未核验”，必须标为待验证推测；不能从成交额推导净流入。Next Question 针对机制、信息事件、历史重复性或表达成本提出最低成本核验。

报告同时生成人可读 `report.md`，含中文摘要、覆盖/失败、最多5条候选、原始数据定位和人工下一步。人工补核机制、数据可靠性及原稿研究触发条件后才把完整证据交 Researcher；不能仅改 eligibility 布尔值放行，不增加新角色/审批系统。暂不改变 Researcher Prompt，也不自动把未核验统计候选上传 Drive Signals/Market。

## 6. 兼容、Actions 与保存

原有 fixture / 单日 Tushare 演示命令与8项测试继续可用；旧报告不改写版本。新增显式 history 模式，不把 `--demo-abs-pct` 偷偷用作正式规则输入。history+fixture 使用含足够历史的独立测试材料，不能把现有三行 fixture 填充成“历史行情”。新入口/参数保持简单，由实现者选择最小扩展并在 README 给直接可复制命令。

Market Sensor workflow 同时支持手动演示、手动历史监测和 schedule。按 event_name 明确选择配置：手动沿用表单默认演示；schedule 必须是 Tushare history + 版本化默认配置，不能依赖不存在的 inputs 默认值。单条 cron `17 20 * * 1-5` 配 `timezone: Asia/Taipei`；生效文件与 tasks/ 副本同步，目标版本0.3.0。沿用 contents:read；不增加写仓库权限或其他长期凭据。

若实际 GitHub workflow 校验明确拒绝 timezone 字段，允许改用等价 UTC cron `17 12 * * 1-5` 并注释台北20:17，将平台拒绝和回退记录入验证文档；不能未经实测把官方当前支持说成不支持，也不为此新增调度服务。

每轮总是尝试保存 report.json/report.md 为 run_id/attempt 唯一 artifact，保留14天；报告写失败要令 workflow 失败。每轮覆盖工作区旧报告，不能上传上轮成功快照；临时抓取原始数据仅在该次 artifact 留存，不自动写 Git。CI 只跑离线，不访问真实API。定时仅在默认分支启用；代码 PR 阶段不得登记自然定时通过。schedule 延迟/丢弃属于平台限制，保留手动指定日期补跑，不另建 scheduler。

## 8. 开发交付与停止条件

从已合并 PR #1 的 main 基线开发，需求先入 Git。实现后将 Market task/code/workflow 版本统一升至0.3.0，更新 CHANGELOG、README、Market task说明、输出约定和验证记录；其他角色/公共协议不虚增版本。保持原稿字节内容。

提交可审查 PR，不自动合并。交付实际改动、测试、可复制命令、run链接/明确未执行项。真实历史取数受权限或平台限制时，可完成离线代码和PR，把受阻项标明；不能因此停止所有实现，也不能用演示填过真实验收。首个自然定时依赖合并，留作合并后验收；不为等定时无限阻塞PR交付。

本规格已经给出开工所需参数；不再以“尚未给市场/阈值/频率”为由暂停。只有与本规格实际冲突、无法兼容现有协议或不可逆动作才提出具体问题；常规实现选择按最小改动处理。

数据与调度依据见 [官方资料核验](market-data-references.md)。阈值、名单和运行时刻是本轮工程试运行选择，官方资料不为其有效性背书。
