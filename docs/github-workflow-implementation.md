## 分步实施

### 1. 核对接入与数据

- 用 gh 检查 repo/default branch、权限、现有 rules/workflows、Pages 设置与失败日志、开放 PR、Issues 状态。
- 核对实际 Judge 任务及其 prompt 的可获得版本，查明定时平台能否在无人值守轮次创建分支/文件/PR。产出可复制的 Judge 更新 prompt 与操作说明；实际平台修改按当前可用入口完成并留回执，能力缺失写为待接通。
- 确认 GitHub 身份、通知路径和实践消费者身份。共用身份下自我审阅限制与通知行为必须实测。不要机械设置无法满足的必需 reviewer。
- 当前根仓库新 Sensor 文档、远端镜像分别核对；迁移只取必要上下文，记录来源。

验收：有固定 SHA、目录清单、平台接入状态及已知缺口，能准确解释 Pages 当前失败。

### 2. 定义协议与确定性校验

- 建立规范所列目录入口、README、JSON schemas 和 `protocols/practice.md`。任务和结果使用 JSON，报告使用 Markdown。
- 校验字段类型、枚举、ID 唯一性、引用存在性、目录安全、时间与数据单位、结果与任务 hash 对应、demo/PILOT 准入禁止。
- PR 分类为 review、practice-result、decision、archive 或 implementation。按类型核对允许变更路径；业务 PR 不得借机改 workflow/校验器。校验 PR 数据时从可信 base 获取校验器，不执行 PR 提供的代码。
- 检查实际 diff 和 GitHub 合并证据，不能接受文件自报审批。变更内容和范围必须显示给审阅者。
- 对旧镜像允许缺机会 ID，保留旧字段与原文。新记录必须遵守新协议，不能批量猜测历史机会身份或把 83 份文档直接变成 83 个机会。

验收：合法 review/result/decision 通过，缺证据、越权路径、无输入结果、重复 ID、过期 task_hash 均被拒绝。

### 3. 合并交接与领取

- 评审 PR 直接包含输入文件，合并即入 main，无额外文件搬运事务。
- 合并后 Actions 幂等创建关联任务 Issue；失败可手动重跑及定时补扫，从 main 重建未建映射。
- 实现协议中的领取/心跳/阻塞/恢复回执处理，任务级串行化并重读租约。
- 编写外部消费者接入说明与最小协议演练命令。可用测试消费者验证握手，标记 synthetic；实践 Agent 本体留在独立项目。
- 结果合并后从结果记录推导任务完成；消费端以任务和结果集合判断，不删除历史输入。
- 结构化人类决定评论验证 actor、action、机会和结果引用，生成决策 PR。重复 webhook/重跑不重复生成。评论编辑后生成新的提案版本，不能静默篡改已合并决定。

验收：同一任务并发申请只确认一个领取；重复轮询/重跑不会重复任务或 PR；关闭提案、修改请求、租约过期和中断恢复有明确状态。

### 4. 看板与计算

扩展现有 site，沿用其设计与有效功能。使用 GitHub Actions 生成静态投影，主分支文件、开放 PR 和运行 Issue 作为输入。状态生成器只解析结构化受验证内容，不使用 LLM 推断状态。

| 展示 | 字段或计算规则 |
| --- | --- |
| 待处理 | 开放 review PR 数、开放 result PR 数、已合并结果且无覆盖决定的机会数，分别展示 |
| 机会卡片 | 标题、客户、经济锚点、四 Gate 摘要、Judge 建议、研究成熟度、流程阶段、关键未知、下一步 |
| 实践卡片 | 问题、判定标准、预算/消耗、领取者、开始/最近心跳、阻塞、最新结果 |
| 状态历史 | 事件时间、动作、actor、来源 PR/Issue/commit；明确计划时间与实际发生时间 |
| 等待时长 | 当前时间减进入该状态时间，缺时间显示未知，禁止当零 |
| 完成率 | 指定创建时间窗口内已合并结果的唯一任务数 / 该窗口已批准唯一任务数；分母零显示无样本 |
| 立项转化 | 同一机会创建批次内已立项唯一机会数 / 已批准验证唯一机会数，同时展示样本数与观察截止日期 |
| 运行新鲜度 | 数据生成、最近 Judge、最近领取/心跳、GitHub 同步与 Pages 部署分别显示 |

主视图为待我处理 + 机会状态列表，详情显示证据与时间线。支持按阶段筛选，点击审阅/决定跳 GitHub 对应入口。320px 宽可读，键盘可操作，空数据、未知值、抓取失败与过期快照有明确显示。金额必须有币种、依据和 measured/estimated/unknown 标记。

公开投影采用字段白名单，仅发布脱敏标题、摘要、统计和允许披露的状态。原始 Research、个人决定理由、私有证据、客户数据和凭据留在私有仓库。公共页面到私有 GitHub 的入口须标明需要仓库权限。沿用只上传 site 的 workflow。

PR/Issue 更新可在受信默认分支处理元数据触发快照刷新，禁止特权 workflow checkout 或执行 PR 分支代码。配置最小权限；需要从 fork 或非受信主体接收内容时按不可信数据处理。内部 GITHUB_TOKEN 产生的事件可能不触发后续 workflow，采用同一工作流显式串联、可复用工作流或受支持的显式 dispatch，并做实际验证。

发布快照尽量直接构建部署 artifact，避免机器人提交导致循环。现有 latest.json 结构应有明确迁移与兼容方案。失败保持上一份快照并显示上次成功时间，不把 API 错误呈现为零机会。

实施约定：保留旧 `latest.json` 与现有视图，另生成 `workflow.json`；只读取记录中独立填写的 `public` 脱敏字段及明确允许的状态、汇总、时间与 GitHub 链接，不从私有原文自动提炼。统计创建窗口默认最近 90 天，页面显示窗口和观察截止时间。任何必要 GitHub API 失败时构建失败、保留已部署的上一快照；未配置 `WORKFLOW_PUBLIC_PROJECTION_APPROVED=true` 时不生成公开闭环快照。此变量只有在用户确认公开字段符合现有范围后才可启用。

验收：待审、待领取、实践中、阻塞、待验收、待决定、立项、暂缓、关闭都能展示；统计用小型已知样本复算；移动与桌面截图检查；页面输出不含私有原文。

### 5. 首轮验收与交付

先用显式 synthetic 数据验证技术路径。真实业务入队需要用户合并真实评审 PR。一次完成路径必须记录以下证据：

1. 评审 PR 创建、实际通知、用户合并的 SHA。
2. main 输入可读取，外部消费者或测试消费者确认领取；注明消费者类型。
3. 实践结果 PR 创建、通知、人合并。
4. 人类决定通过决策 PR 入库，下一轮 Judge 能读回。
5. 看板相应状态和指标更新，Pages deployment 成功且实际 URL 可访问。

测试重点还包括同机会多个任务、重复提交、合并后 Issue 创建失败、领取竞争、过期租约、关闭未合并结果、API 部分失败、未来/缺失时间、未知金额和脱敏检查。只增加能捕捉具体回归的测试。

最终交付包含实现 PR、协议入口、Judge prompt、测试结果、看板 URL/截图、外部实践项目接入清单和未接通项。不能把模拟消费者或手动 gh 提交算作平台定时与真实实践项目已验收。发现平台限制时完成其余工作，具体列出受阻环节。
