# Drive 单向同步与看板

目标是由 GitHub Actions 每三小时只读扫描指定 Drive 根目录及所有子目录，将文件内容与目录元数据单向镜像到 GitHub，并让 Pages 重新生成资料索引。Drive 是输入端，GitHub 不修改 Drive。

## 范围和边界

- 覆盖根目录下所有文件夹与文件，包括 Signals、Research、Judge 和 Archive；按 Drive ID 去重并保留原名、目录路径、类型、修改时间、来源链接与文件哈希。不能将运行回执和系统资料当成机会。
- Google 文档导出为纯文本，表格和演示文稿分别导出为 xlsx 和 pptx，普通文件保留原始字节。导出不保证原生文档的排版、评论和嵌入内容完整；不支持或不能读取的文件须报告失败，不能悄悄漏掉。
- 完整递归枚举和读取均成功后才更新 GitHub；任何分页、权限、类型或下载失败都停止提交并保留上一次成功结果。源文件暂时不可见时保留 GitHub 历史，并标为未见到，不推断源文件已删除。
- 不改变原 `or-archive/` 和原始业务文档。新镜像写入 `drive-mirror/`，页面按 Drive ID 合并既有历史与新镜像，避免重复；不从镜像自动生成已批准机会或实践任务。
- 目标仓库及 Pages 公开。同步的所有文件及 Git 历史也将公开；同步默认关闭，身份、读取范围和公开后果明确后才启用。

## 认证与运行

- Actions 使用绑定仓库和默认分支的 Google Workload Identity Federation 和独立服务账号；只申请 Drive 只读 scope。目标根目录需共享给该服务账号，是否能够读取每个子项以实际扫描为准。
- 定时和手动触发从可信默认分支运行，禁止执行 Drive 内容；同步仅写入 `drive-mirror/`。无内容变化不创建提交。GitHub 内置 token 创建的提交可能不触发其他工作流，因此同步完成后显式触发 Pages 生成和部署。
- 目录、文件 ID 和完整扫描结果决定镜像；名称冲突以 ID 区分，路径经过安全处理。只读和写入的失败必须在运行结果中可见，不将失败显示为空目录。
- 本地用隔离的模拟 Drive 服务验证分页、嵌套、不同文件类型、更新、无变化、源不可见、失败回滚及页面索引；随后以真实授权身份完成在线验证。未实际配置或验证前不声称自动同步已接通。

详细操作见 [开通 Google Drive 单向同步](drive-sync-setup.md)。
